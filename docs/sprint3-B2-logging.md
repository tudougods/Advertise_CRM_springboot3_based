# Sprint 3 B2 日志分级与安全检查

## 日志规则

| 级别 | 当前使用场景 |
| --- | --- |
| `ERROR` | 未知系统异常、已识别的 5xx 服务端故障；保留一次异常堆栈 |
| `WARN` | 401/403 安全拒绝、409 业务冲突、429 限流、数据库约束冲突 |
| `INFO` | HTTP 请求完成、账户消费、充值订单创建、模拟支付和可信回调完成 |
| `DEBUG` | 参数问题、资源不存在等可预期的普通业务失败 |

每次 HTTP 请求完成日志包含请求方法、URI 路径、响应状态和耗时。`requestId` 存储在 MDC 中，并通过日志格式 `%X{requestId:-}` 输出，因此同一次请求中的异常日志和业务日志可以关联。

## 敏感信息检查

- 请求日志不读取或输出请求体、查询参数和请求头。
- 不记录密码、密码摘要、JWT、回调签名、验签密钥或原始回调载荷。
- 资金状态变化日志只记录业务编号、订单编号、事件编号、结果和数据库 ID，不记录密钥或用户提交的备注。
- 异常响应继续使用安全的客户端消息；未知异常的内部信息只进入服务端 `ERROR` 日志。

## 自动化验证

- 请求日志测试检查 `requestId`、方法、路径、状态和耗时，并用带密码、JWT 的模拟请求验证敏感内容不会进入日志。
- 异常日志测试分别验证可预期失败、冲突、已识别服务端故障和未知异常的日志级别。
- 未知异常测试同时确认只产生一条带堆栈的 `ERROR` 事件。
