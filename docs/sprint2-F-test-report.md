## 4. 数据与环境隔离

- F1 的 60000 条投放数据以及账户、订单、流水、回调数据只在事务中生成，脚本结束时全部回滚；identity sequence 不随事务回滚，因此脚本拒绝在默认开发库 `advertiser_crm` 上执行，必须使用可丢弃的独立验收库。
- F2 使用独立临时数据库 `advertiser_crm_f2`，验收后停止临时应用并删除该数据库。
- F3 自动化回归通过 Testcontainers 使用一次性 PostgreSQL 16，不读写日常开发数据库；此前验收复核的核心业务表均为 0 行，Flyway 版本为 V10。
- 回调密钥只通过环境变量提供，文档和仓库不保存真实密钥。

## 5. 性能与边界

- F1 验证的 13 类访问路径均使用既有合适索引；4 行广告类型字典使用顺序扫描属于合理成本选择，无需新增索引或迁移。
- 本地固定数据集最慢的日期趋势查询约 2.09 ms。该结果用于验证执行计划，不等同于生产容量测试或 SLA。
- Sprint 2 仅实现本地模拟支付，不连接真实支付平台；生产接入仍需补充支付方 SDK、网络异常处理和密钥托管。
- 当前未引入缓存，因为验收没有发现需要缓存解决的热点。
- JDK 21 下测试日志包含 Mockito 动态代理预警，不影响本次结果；升级未来 JDK 时应按 Mockito 指引改为显式 Java Agent。
- Swagger/OpenAPI 用于开发与演示，生产部署时应根据环境策略限制暴露。

## 6. 总验收结论

Sprint 2 的功能、数据库约束、权限、事务一致性、并发幂等、查询计划、真实 HTTP Demo 和自动化回归均已通过。板块 F 未发现需要修改业务代码的阻塞问题，可以进入分支推送、PR 和合并流程。
